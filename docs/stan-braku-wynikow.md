# Stan braku wyników — etap [23]

`/sklep` pokazuje ten widok dopiero po udanym pobraniu odpowiedzi z `GET /products`, gdy `total = 0` i istnieje niepuste `q` lub aktywne zawężenie. Dla samego wyszukiwania nagłówek zawiera bezpiecznie escapowane hasło; dla samych filtrów używany jest komunikat o niespełnionych filtrach, bez sugerowania braku materiałów na dany temat. Połączenie `q` i filtrów zachowuje oba konteksty. Pusta lista bez wyszukiwania i filtrów pozostaje zwykłym pustym katalogiem.

Stan nie jest renderowany podczas pobierania ani błędu. Ładowanie korzysta ze szkieletów, błąd ma przycisk ponowienia. `total > 0` przy pustych `items` oznacza stronę poza zakresem, a nie brak dopasowań; użytkownik może przejść na pierwszą stronę. Nie ma automatycznego przekierowania.

Publiczne ustawienie `catalog.search_empty.v1`, udostępniane przez allowlistę `GET /catalog/public/search-presentation`, zawiera `suggested_queries`, opcjonalny `contact_email` i opcjonalny `contact_phone`. Domyślna lista to „integracja sensoryczna”, „terapia ręki”, „nadwrażliwość”, „voucher”. Kontakt domyślnie nie jest skonfigurowany: UI nie tworzy zastępczych adresów ani martwych linków i pokazuje krótką informację o braku danych. Seed jest idempotentny i nie nadpisuje wartości operatora. Walidacja dopuszcza tylko e-mail oraz numer telefonu w formacie bezpiecznym dla `mailto:`/`tel:`.

Popularne zapytania w `suggestions.popular_queries` pochodzą z historii `search_queries` i pozostają odrębne od redakcyjnych `suggested_queries`. Produkty pokrewne i ich dane pobierane są z odpowiedzi wyszukiwania [16], maksymalnie trzy, bez dodatkowych zapytań dla każdej karty. API nie pokazuje rekomendacji jako wyników: `total` pozostaje zerem.

Wyszukanie przez użytkownika używa nawigacji Next.js i zachowuje filtry, sortowanie oraz `per_page`; resetuje stronę. „Wyczyść filtry” usuwa wyłącznie category/kind/audience/price_min/price_max/delivery, resetuje page i zachowuje q, sort oraz per_page. Pole robocze synchronizuje się z URL po Wstecz/Dalej. Wyszukiwanie zapisuje się w `search_queries` przez endpoint [16], nie przez render komponentu. Parametr `record_search=false` jest używany wyłącznie przez pomocnicze żądanie SSR liczące fasety bez kategorii, by nie utworzyć drugiego wpisu dla tej samej nawigacji; domyślne żądania publiczne nadal zapisują zakończone wyszukiwanie, także po cache hit.

Lokalnie uruchom testy UI komendą `npm --prefix apps/web run a11y` (serwer i API fixture są uruchamiane przez Playwright), a testy API z `apps/api` komendą `uv run --frozen --all-groups pytest tests/test_public_catalog.py`. Testy fixture potwierdzają rendering, URL i bezpieczne wyświetlenie; rzeczywiste dane produktów zależą od zawartości katalogu. Brak publicznych danych kontaktowych nie jest zastępowany danymi przykładowymi.
